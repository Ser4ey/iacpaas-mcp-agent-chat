# Проверка 2 ноября 2026 (финальная доработка): локальная модель, свежесть индекса, MCP

Доработки к защите: явная поддержка локальной модели (LM Studio, Ollama) и устойчивость к провайдеру без ключа, цен и окна контекста; сверка индекса с платформой по датам изменения ресурсов при запуске; раздел README «Как использовать MCP-сервер».

## Автоматические проверки

`pytest`: 282 теста, все проходят (без сети и платных запросов). Новые проверки:

- какие адреса модели считаются локальными (localhost, 127.0.0.1, ::1, частные сети, `host.docker.internal`, имя без точки) и как их переопределяет `MODEL_LOCAL`; для локального адреса ключ не нужен (`configured`, чат и проверка ответа), клиенту уходит заглушка; таймаут — из `MODEL_TIMEOUT_SECONDS`, повтора после тайм-аута нет;
- окно контекста: из родного API LM Studio (`loaded_context_length`), из `MODEL_CONTEXT_TOKENS` или по умолчанию 32 768 с пометкой `context_source`;
- стоимость: локальная модель без цен — `free: true` и «бесплатно»; облачная без цен и без `usage.cost` — `cost: null` и в ответе, и в сумме диалога, а не 0; подписи интерфейса (`static/format.js`, проверяются в Node.js) не показывают «0,00 ₽» без данных;
- ошибки локального сервера: не запущен, нет модели (404), переполнено окно (400 с текстом сервера), тайм-аут — понятный текст с подсказкой;
- `<think>…</think>` не попадает в ответ, в историю и в разбор отчёта проверяющего, в том числе когда тег разрезан между кусками потока;
- полный стек «HTTP → агент → настоящий MCP → индекс» с двойником локального сервера без ключа, цен и окна в каталоге: ход и проверка ответа проходят, стоимость — «бесплатно»; с остановленным локальным сервером — ошибка «Локальный сервер модели не отвечает по адресу …»;
- свежесть индекса с подменённой платформой: дата не изменилась — полной выгрузки нет; изменилась у одного ресурса — переиндексирован только он; ошибка платформы при сверке — индекс не тронут, ошибка синхронизации не записана; ресурса нет в индексе — загружается; веб-приложение при старте сверяет даты в фоне и сразу отвечает (индекс готов, `checking: true`).

## Локальная модель

Машина: Intel Core Ultra 7 155H, встроенная Intel Arc (драйвер 31.0.101.5382), 32 ГБ памяти; LM Studio с движком llama.cpp Vulkan.

- Скачана `qwen3-4b-instruct-2507` (Qwen3-4B-Instruct-2507, Q4_K_M, 2 497 280 448 байт, SHA-256 совпал с Hugging Face). `lms get` не смог скачать её («fetch failed»), файл скачан напрямую в папку моделей LM Studio, `lms ls` его увидел.
- `lms load qwen3-4b-instruct-2507 --context-length 32768 --gpu max -y` — загрузка 1 минута 59 секунд, 2,33 ГБ. `lms ps` показал окно 99 840 и четыре параллельных слота, а не 32 768.
- Ответы API LM Studio совпали с тем, на что рассчитано приложение: `GET /v1/models` — только `id` моделей, без окна и цен; `GET /api/v0/models/qwen3-4b-instruct-2507` — `state: "loaded"`, `max_context_length: 262144`, `loaded_context_length: 99840`, `capabilities: ["tool_use"]`.
- **Вопросы через веб-чат на локальной модели не прогонялись.** Проверку остановили во время повторной загрузки модели: модель перегружала ноутбук. Как `qwen3-4b-instruct-2507` отвечает на «Сколько существует материалов с содержанием железа больше 5%?» и «Какой химический состав у стали 12Х18Н10Т?», скорость ответа и соблюдение `tool_choice` сервером LM Studio — не проверены. Ollama не проверялась.
- Веб-приложение с локальным адресом, на котором сервер не запущен (`ROUTERAI_BASE_URL=http://127.0.0.1:1235/v1`, ключ пустой; порты 8050/8051): статус `configured: true` без ключа, провайдер «Локальная модель», `free: true`, `context_source: "default"`, окно 32 768, бюджет 28 672. Вопрос — через 2 секунды ошибка «Локальный сервер модели не отвечает по адресу http://127.0.0.1:1235/v1. Запустите его (LM Studio: «lms server start», Ollama: «ollama serve») и повторите вопрос.», ход сохранён, диалог не заблокирован. Интерфейс (Playwright): подсказка к модели — «Бесплатно: модель работает на локальном сервере» и «Окно контекста: 32 768 токенов — по умолчанию…»; в списке диалогов и под ответами — «бесплатно» и «стоимость неизвестна», в шапке — «диалог бесплатно» и «диалог —»; ошибок в консоли нет.

## Автоматические проверки

- сквозной прогон «HTTP → агент → настоящий MCP-сервер»: `confirm_request` в потоке, решение через эндпоинт, итог в журнале и в сохранённом диалоге, повторное решение — `404`; закрытая страница во время карточки — ход отменён, запись не выполнена.

История с вызовами инструментов принята провайдером на следующем ходе. RouterAI для этой модели не присылает `reasoning_details` (их нет и в диалогах, сохранённых прежней версией), поэтому их поддержка проверена тестом. Стоимость — фактическая из `usage.cost`.

Модель сама выбирает, сколько вершин дочитать. На вопрос о составе вышло 9 вызовов против 6 накануне; это число меняется от прогона к прогону.

### Окружение и Docker

- **`.venv` пересобрано.** Прежнее было создано от Python из служебного кэша Codex. Новое создано от Python 3.12.13, установленного через uv (по ссылке `cpython-3.12`, которая переживает обновление патч-версии). Пакеты поставлены из `requirements-lock.txt`, и список установленных версий совпадает с ним полностью. 67 тестов проходят.
- **Docker.** `Dockerfile` теперь ставит зависимости из `requirements-lock.txt` отдельным слоем, а сам проект — без зависимостей. `docker compose build` прошёл; первая сборка заняла около 11 минут, почти всё время ушло на загрузку базового образа и пакетов. Образ весит 394 МБ. После `docker compose up` контейнер ответил на `/api/status`: ключ и модель настроены, индекс готов (94 569 вершин из смонтированной папки `data`), каталог RouterAI загружен (рубли, окно 1 048 576). ### Замечания

- **Модель дочитывает компоненты по одному.** На вопрос о составе без платформы она читала каждый компонент отдельным вызовом (11–16 вызовов, 0,7–1,2 ₽), хотя описание `get_subgraph` советует читать запись одним вызовом. Лимит вызовов и финальный шаг не дают этому выйти из-под контроля.
- **Промежуточные фразы попадают в ответ.** Перед вызовом инструментов модель иногда пишет «Сначала посмотрю…»; это часть ответа. Один раз такая фраза была по-английски.
- **Подпись валюты в первые секунды.** Если вопрос задан, пока каталог моделей RouterAI ещё загружается (приложение ждёт его до 20 с), стоимость в ответе считается верно, но без подписи валюты.

## Расход

- Окно контекста из каталога RouterAI: 1 048 576 токенов, бюджет истории 1 044 480.
- Вопрос о составе 12Х18Н10Т: 6 вызовов инструментов, около 51 тысячи входных токенов, 0,40 ₽. До облегчения выдачи подграфа было 15 вызовов и 0,73 ₽.
