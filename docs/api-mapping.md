# MCP-инструменты и API IACPaaS

Названия инструментов — интерфейс нашего адаптера. Они не означают наличие одноимённых HTTP endpoints в IACPaaS. Общая логика одинакова для stdio и Streamable HTTP (`materials_chat/service.py` — чтение, `materials_chat/writes.py` — запись и чтение по пути).

## Используемые операции платформы

| Операция | HTTP-запрос | Для чего используется |
|---|---|---|
| Вход | `POST /api/signin` | Получить JWT по логину и паролю (действует 24 часа, обновляется автоматически) |
| Экспорт ресурса | `GET /api/data/export/user-item?path=…&json-type=universal` | Полная загрузка ресурса в локальный индекс |
| Экспорт фрагмента | то же + `start-target-concept-path=/…` и `export-depth=N` | Живое чтение вершины и её подграфа |
| Создание папки | `POST /api/storage-unit/folder/create` `{path, name, description}` | `create_folder`: `path` — родительская папка («» — корень фонда) |
| Импорт ресурса | `POST /api/data/import` `{path, json, clearIfExists}` | `create_resource` (`clearIfExists: false`) и `update_concept` (переимпорт, `clearIfExists: true`) |
| Удаление ресурса | `DELETE /api/data/delete` `{path, mode}` | `delete_inforesource`: `trashIR` — в корзину, `deleteIR` — безвозвратно |

- `path` — путь относительно «Мой Фонд», например `Загрузки / Справочник по материалам`.
- `start-target-concept-path` — путь к вершине **внутри ресурса**: имена вершин от корня через `/`, начиная с `/` и без самого корня. Пример: `/Сплавы на основе железа/12Х18Н10Т`. Имя, в котором есть `/`, заключается в тройные кавычки: `/Физические свойства/Плотность вещества/‴кг/м³‴`. Другие варианты платформа отклоняет: «путь должен начинаться с символа 'слеш' (и не включать корневое понятие)».
- `export-depth` — глубина от этой вершины (0 — только она сама). Платформа дополнительно отдаёт цепочку от корня до вершины; адаптер спускается по ней и проверяет, что `id` совпадает с ожидаемым.

Авторизация — `Authorization: Bearer …`. Ответ экспорта содержит JSON графа строкой в поле `data`; адаптер разбирает оболочку и проверяет формат. Ответ записи — `{success, code, explanationSafe, platformUnavailable}`: при `success: false` в ответ инструмента идёт `explanationSafe` без имён Java-исключений (код `PLATFORM_REJECTED`). [Официальное описание HTTP API](https://iacpaas.dvo.ru/docs/RemoteCalls/RemoteCalls.html), формат ресурса — [Json.html](https://iacpaas.dvo.ru/docs/Json/Json.html).

Особенности записи, проверенные на платформе 02.11.2026:

- Импорт принимает минимальный universal JSON без `id`: `title` (имя ресурса, оно же `name` корня), `json_type: "universal"`, `ontology` — полный путь онтологии (`<e-mail> / Мой Фонд / Загрузки / Онтология …$;`), `type: "КОРЕНЬ"`, `meta` — название онтологии; у вершин `type: "НЕТЕРМИНАЛ"`, `name`, `meta` (имя понятия), у значений `type: "ТЕРМИНАЛ-ЗНАЧЕНИЕ"`, `value`, `valtype`, `meta`. `path` импорта — папка-контейнер.
- Платформа сама проверяет онтологию, включая ограничители отношений: собственное значение по отношению с ограничителем `clone` (например, «единица измерения» в базе свойств — клон вершины Системы единиц) отклоняется. Сервер отказывает в таких вершинах заранее.
- `PUT /api/data/update` не работает при любых аргументах: платформа отвечает «Неожиданное значение параметра action: updateVertice». Поэтому `update_concept` меняет вершину переимпортом: свежая выгрузка ресурса → правка вершины → импорт с `clearIfExists: true`. Ресурс тот же (`code` не меняется), у вершин новые `id`. Если импорт не прошёл, сервер импортирует исходную выгрузку обратно.
- Удаление несуществующего ресурса платформа отклоняет внутренней ошибкой, поэтому сервер перед удалением проверяет ресурс экспортом корня и отвечает `NODE_NOT_FOUND`. Перед созданием ресурса — тоже: импорт поверх существующего ресурса слил бы содержимое.

## Сопоставление

| MCP tool | Назначение | Что фактически выполняется | `meta.served_from` |
|---|---|---|---|
| `list_inforesources` | Список разрешённых ресурсов | Фильтрация `config/resources.json` и состояние индекса | `configuration` |
| `get_inforesource` | Метаданные ресурса; у онтологий проекта — дерево понятий `structure` | Экспорт корня (`export-depth=0`): дата изменения, онтология, комментарий; размер графа — из индекса. С `path` — любой ресурс «Моего фонда», только с платформы | `iacpaas_live` |
| `search_graph` | Лексический поиск по вершинам | SQLite FTS5 по локальной копии: у платформы нет поиска по тексту | `local_index` |
| `find_materials` | Подбор марок по химическому составу: условия на элементы, класс, сортировка, страницы; точное число подходящих марок (`total`) одним вызовом | Расчёт по таблице состава (`materials_chat/composition.py`), построенной из локального индекса: диапазоны содержания, гарантированное сравнение; основа «не более X» — остаток до 100 % | `local_index` |
| `get_subgraph` | Вершина и её окрестность до глубины 8 | Путь к вершине берётся из индекса → экспорт фрагмента с платформы → та же постраничная выдача. С `path` — любой ресурс «Моего фонда»: `root` — путь вершины, у вершин в выдаче `concept_path`, без индекса и запасного снимка | `iacpaas_live` |
| `count_graph` | Число вершин и дуг; с `concept` — число вершин понятия онтологии и их имена (до 50) | Обход графа в индексе (весь справочник — около 0,3 с); неизвестное понятие — `UNKNOWN_CONCEPT` со списком понятий ресурса | `local_index` |
| `validate_resource` | Проверка структуры ресурса; с `ontology` и `items` — проверка дерева будущего ресурса без записи | Локальная проверка формата, онтологии и непустоты; дерево — та же проверка по онтологии, что у `create_resource`: `valid`, `issues`, `description` | `local_index` |
| `write_inforesource` | Создание папки (`create_folder`), ресурса по онтологии (`create_resource`), изменение вершины (`update_concept`) | Защита пути → проверка дерева по онтологии из индекса и сборка universal JSON → подтверждение пользователя → `folder/create` или `import` | `iacpaas_live` |
| `delete_inforesource` | Удаление ресурса в корзину или безвозвратно | Защита пути → проверка, что ресурс есть → подтверждение → `data/delete` | `iacpaas_live` |

Читающие инструменты помечены аннотацией MCP `readOnlyHint: true`, записывающие — `readOnlyHint: false`, `destructiveHint: true` (по определению MCP `false` значит «только добавляет», а изменение вершины меняет существующее). При `WRITE_ENABLED=false` записывающих инструментов и параметра `path` у чтения нет.

Когда живое чтение базового ресурса невозможно, `get_subgraph` и `get_inforesource` отвечают из индекса с `served_from: local_index_fallback` и причиной в `meta.live_error`:

| Код | Причина |
|---|---|
| `PLATFORM_UNAVAILABLE`, `PLATFORM_TIMEOUT`, `ACCESS_DENIED`, `PLATFORM_REJECTED` | Ошибка сети, доступа или ответа платформы |
| `PATH_NOT_FOUND` | Путь к вершине не удалось восстановить по индексу (например, индекс обновился во время запроса) |
| `NODE_MOVED` | На платформе по этому пути другая вершина: ресурс изменился после индексации |

Фрагменты больше `LIVE_MAX_NODES` (5000 вершин) читаются из индекса (`meta.live_skipped`). Повторное чтение того же фрагмента в течение минуты берётся из кэша; после записи кэш по ресурсу сбрасывается. Чтение по `path` индекса не использует: при ошибке платформы возвращается ошибка.

`query_graph` из задания реализован как `find_materials`: это поддерживаемый запрос с ограниченными параметрами (условия на состав марок, класс, сортировка, страницы). Вопрос «сколько марок, где железа больше 5 %» — один вызов с точным `total` (1 026 по индексу на 02.11.2026), «сколько свойств в базе» — `count_graph` с `concept: "Свойство"` (28). Произвольный язык графовых запросов не заявляется. Лексический поиск по тексту — `search_graph`. Методы внутреннего Java API IACPaaS внешнему приложению недоступны и не выдаются за HTTP endpoints.

## Запись: `write_inforesource` и `delete_inforesource`

`write_inforesource` из задания — один инструмент с аргументом `request`; вариант выбирает `request.operation`, у каждого варианта свои обязательные поля в JSON Schema:

| `operation` | Поля | Что делает сервер |
|---|---|---|
| `create_folder` | `parent_path` (пусто — корень фонда), `name`, `description` | Создаёт папку |
| `create_resource` | `folder_path`, `name`, `ontology` (`materials_ontology`, `properties_ontology`, `characteristics_ontology`), `comment`, `items` — дерево `{concept, name или value, comment, children}` | Проверяет дерево по онтологии, собирает universal JSON и импортирует |
| `update_concept` | `path` ресурса, `concept_path` вершины, `name` и/или `value`, `comment` | Читает ресурс, проверяет вершину и тип значения, переимпортирует ресурс с изменённой вершиной |

`delete_inforesource`: `path`, `mode` — `trash` (по умолчанию) или `delete`.

Модель и пользователь не пишут JSON платформы. Сервер берёт онтологию из локального индекса и проверяет:

- понятие допустимо под родителем: потомки понятия, варианты альтернативы, потомки понятия-ссылки (по `link_id`, внутри трёх онтологий проекта), потомки отношений-«пропусков» — прямо под родителем;
- у вершины — элемента множества или списка есть имя; у остальных вершин имя по умолчанию — имя понятия;
- значение подходит по типу: `REAL` — число (строка-число допустима), `INTEGER` — целое, `STRING` — строка.

Не поддерживаются (отказ `UNSUPPORTED_ONTOLOGY_FEATURE`): ограничители `ref`, `clone`, `ref-clone` (ссылка или клон вершины другого ресурса — например, химический элемент в составе марки или единица измерения свойства), фиксированные значения онтологии, типы `DATE`, `BLOB`, `BOOLEAN`, понятия из онтологий вне проекта. Структуру онтологии модель читает через `get_inforesource(resource_id=<онтология>)`, поле `structure`: строки «понятие [вид]» с отступами.

Защита: базовые ресурсы из `config/resources.json`, папка «Загрузки» целиком и пути из `PROTECTED_PATHS`. Путь сравнивается по сегментам без учёта регистра и лишних пробелов, префикс «Мой Фонд» и `<e-mail> / Мой Фонд` снимается, поэтому обходные написания тоже защищены. У создания проверяются родитель и итоговый путь, у изменения и удаления — путь ресурса. Отказ `PROTECTED_RESOURCE` приходит раньше подтверждения и любого запроса к платформе.

Подтверждение — MCP elicitation (`ctx.elicit`): текст строит сервер из фактических аргументов, запись выполняется только при явном «Подтвердить». Отклонение — `CONFIRMATION_DECLINED`, нет ответа за `WRITE_CONFIRM_TIMEOUT_SECONDS` (120 с) — `CONFIRMATION_TIMEOUT`, клиент без elicitation — `CONFIRMATION_UNAVAILABLE`. По HTTP elicitation работает только в режиме с сессией, поэтому MCP-сервер запущен с `stateless_http=False, json_response=False`.

Коды ошибок записи: `PROTECTED_RESOURCE`, `FOREIGN_CONCEPT` (вершина — ссылка или клон вершины другого ресурса), `AMBIGUOUS_PATH` (одноимённые соседи), `CONCEPT_NOT_ALLOWED` (с перечнем допустимых понятий), `INVALID_VALUE`, `UNSUPPORTED_ONTOLOGY_FEATURE`, `NODE_NOT_FOUND`, `INVALID_ARGUMENTS`, `CONFIRMATION_DECLINED`, `CONFIRMATION_TIMEOUT`, `CONFIRMATION_UNAVAILABLE`, `PLATFORM_REJECTED`, `PLATFORM_UNAVAILABLE`, `PLATFORM_TIMEOUT`, `ACCESS_DENIED`. Каждая попытка записи — одна строка в журнале MCP-сервера, без секретов.

## Результаты и ошибки

Результат содержит полезные данные, источник (`served_from`, `indexed_at` или `fetched_at`) и признаки ограничения выборки (`has_more`, `next_offset`, `truncated`). В подграфе у вершин нет повторяющихся полей: структуру задают дуги `edges`, полный путь указан только у корня. Вершина, часть потомков которой не попала в выдачу (по глубине или странице), помечена полем `children_not_loaded` с их числом.

Следует различать:

- Успешный поиск без совпадений: в выбранном снимке и по данному запросу сведений нет.
- Неизвестный идентификатор или путь: ошибка параметров, а не отсутствие материала.
- Отказ доступа: пользователь не может прочитать ресурс.
- Ошибка сети, таймаут или ошибка формата: данные получить не удалось.
- Достигнут лимит: получена часть результата; нужно сузить запрос или читать следующий фрагмент.

Ошибка передаётся модели как диагностируемый результат инструмента. Агент может исправить аргументы или объяснить проблему, но не должен заменять ошибку вымышленным ответом.

## Что намеренно отсутствует

- Добавление вершин в уже существующий ресурс, копирование фрагментов, импорт произвольного JSON, удаление и очистка подграфов, очистка ресурса (`clearIR`, `deleteSubGraph`, `clearSubGraph`).
- Ссылки и клоны вершин других ресурсов при создании, проверка множественности (`specifier`), ресурсы по онтологиям вне трёх онтологий проекта.
- Удаление и переименование папок, листинг фонда (в HTTP API его нет: путь агент узнаёт от пользователя или из своей записи), поиск и подсчёт по небазовым ресурсам, пакетные операции.
- Запуск сервисов платформы. У модели нет произвольного HTTP-клиента: только инструменты адаптера.
